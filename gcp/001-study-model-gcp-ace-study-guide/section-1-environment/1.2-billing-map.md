## 1. Billing Architecture

```
  ┌────────────────────────────────────────────────────────────────────────┐
  │                         BILLING ARCHITECTURE                           │
  └────────────────────────────────────────────────────────────────────────┘

  ┌─────────────────┐
  │  Organization   │
  │ (mycompany.com) │
  └────────┬────────┘
           │ contains, BUT billing accounts sit ALONGSIDE the hierarchy
           │
   ┌───────┴───────────────────────────────────────┐
   │                                               │
   ▼                                               ▼
  ┌────────────────────────┐         ┌────────────────────────┐
  │  Billing Account A     │         │  Billing Account B     │
  │  (Engineering)         │         │  (Marketing)           │
  │  Payment: Credit Card  │         │  Payment: Invoice      │
  └──────┬──────┬──────────┘         └──────┬─────────────────┘
         │      │                           │
         ▼      ▼                           ▼
   ┌────────┐┌────────┐              ┌────────────┐
   │Proj A  ││Proj B  │              │ Proj C     │
   │$150/mo ││$300/mo │              │ $200/mo    │
   └────────┘└────────┘              └────────────┘


  ┌──────────────────────────────────────────────────────────────────┐
  │  KEY RULES                                                       │
  ├──────────────────────────────────────────────────────────────────┤
  │  - 1 Project  ──►  1 Billing Account (at a time, can switch)     │
  │  - 1 Billing Account  ──►  MANY Projects                         │
  │  - No billing account = no billable resources                    │
  │  - Billing accounts sit ALONGSIDE the hierarchy (not inside it)  │
  │  - Org IAM does NOT grant billing roles automatically            │
  └──────────────────────────────────────────────────────────────────┘
```

### Billing Account Types

```
  ┌───────────────────────────────────┬───────────────────────────────────┐
  │      SELF-SERVE (Online)          │      INVOICED (Offline)           │
  ├───────────────────────────────────┼───────────────────────────────────┤
  │  Credit/debit card or bank        │  Google sends monthly invoices    │
  │  Charges automatically            │  Net-30 / Net-60 payment terms    │
  │  Instant setup                    │  Requires application + approval  │
  │  Good for: small/medium orgs      │  Good for: large enterprises      │
  └───────────────────────────────────┴───────────────────────────────────┘
```

## 2. Billing IAM Roles

```
  ┌──────────────────────┬──────────┬──────────┬──────────┬──────────┬──────────┐
  │  Capability          │ creator  │  admin   │  user    │ viewer   │ proj-    │
  │                      │ (org)    │          │          │          │ Manager  │
  ├──────────────────────┼──────────┼──────────┼──────────┼──────────┼──────────┤
  │ Create billing accts │    X     │          │          │          │          │
  │ Manage payments      │          │    X     │          │          │          │
  │ Link/unlink projects │          │    X     │    X     │          │    X     │
  │ View costs/reports   │          │    X     │          │    X     │          │
  │ Manage budgets       │          │    X     │          │          │          │
  └──────────────────────┴──────────┴──────────┴──────────┴──────────┴──────────┘

  Roles:
    creator     = roles/billing.creator           (org-level)
    admin       = roles/billing.admin             (billing account)
    user        = roles/billing.user              (billing account)
    viewer      = roles/billing.viewer            (billing account)
    projManager = roles/billing.projectManager    (PROJECT side)
```

### Linking a Project -- The Two-Role Combo

```
                 ┌──────────────────────────────────────┐
                 │  To LINK a project to a billing acct │
                 │  the user needs roles on BOTH sides: │
                 └──────────────────┬───────────────────┘
                                    │
              ┌─────────────────────┴─────────────────────┐
              ▼                                           ▼
  ┌─────────────────────────┐                ┌─────────────────────────┐
  │  ON THE BILLING ACCT    │      AND       │  ON THE PROJECT         │
  │  roles/billing.user     │ ◄──────────►   │  roles/billing.projMgr  │
  └─────────────────────────┘                └─────────────────────────┘

  EXAM TIP: Owner on the project is NOT enough.
  Billing accounts live OUTSIDE the project hierarchy.
```

## 3. Budgets and Alerts -- Process Flow

```
  Step 1                Step 2              Step 3              Step 4
  CREATE BUDGET         SET THRESHOLDS      CHOOSE NOTIFY       OPTIONAL: AUTOMATE
  ┌────────────┐        ┌─────────────┐     ┌──────────────┐    ┌──────────────────────┐
  │ Scope:     │        │ 50% actual  │     │ Email admins │    │ Budget Alert         │
  │ - Billing  │───────►│ 90% actual  │────►│   & users    │───►│       │              │
  │   account  │        │ 100% actual │     │ Pub/Sub topic│    │       ▼              │
  │ - Projects │        │ 100% forec. │     │              │    │ Pub/Sub Topic        │
  │ - Services │        │ (custom %)  │     └──────────────┘    │       │              │
  │ - Labels   │        └─────────────┘                         │       ▼              │
  │            │                                                │ Cloud Function       │
  │ Amount:    │                                                │       │              │
  │ - Specified│                                                │   ┌───┴───┐          │
  │ - Last mo  │                                                │   ▼       ▼          │
  └────────────┘                                                │ Disable  Slack       │
                                                                │ billing  webhook     │
                                                                └──────────────────────┘

  ┌───────────────────────────────────────────────────────────────────────┐
  │  WARNING: BUDGETS DO NOT CAP SPENDING                                 │
  │  They only NOTIFY. To enforce a hard cap, you need:                   │
  │      Budget ──► Pub/Sub ──► Cloud Function ──► Disable billing API    │
  └───────────────────────────────────────────────────────────────────────┘
```

## 4. Billing Export -- Decision Flow

```
  Need to analyze billing data?
         │
         ▼
  ┌──────────────────────────────────────────────────────────────────┐
  │  WHERE should billing data go?                                   │
  └──────────────┬────────────────────────────┬──────────────────────┘
                 │                            │
                 ▼                            ▼
  ┌──────────────────────────┐  ┌──────────────────────────────────┐
  │  BigQuery (RECOMMENDED)  │  │  Cloud Storage                   │
  ├──────────────────────────┤  ├──────────────────────────────────┤
  │  - Near real-time        │  │  - File archive                  │
  │  - SQL queries           │  │  - Long-term retention           │
  │  - 3 export schemas:     │  │  - Compliance archives           │
  │    1. Standard usage     │  │                                  │
  │    2. Detailed usage     │  │                                  │
  │       (per-resource)     │  │                                  │
  │    3. Pricing data       │  │                                  │
  └──────────────────────────┘  └──────────────────────────────────┘

  KEY FACTS
  ─────────
  - Exports are FORWARD-ONLY (no historical backfill)
  - Exports are configurable in CONSOLE only (not gcloud)
  - You can run BOTH BigQuery AND Cloud Storage exports
```

### Standard vs Detailed Schema

```
  ┌──────────────────────────────────┬──────────────────────────────────┐
  │  STANDARD USAGE COST             │  DETAILED USAGE COST             │
  ├──────────────────────────────────┼──────────────────────────────────┤
  │  Per-SKU charges                 │  Adds RESOURCE-LEVEL granularity │
  │  Default for most teams          │  e.g. cost per individual VM     │
  │  Smaller, cheaper to store       │  Larger, more storage cost       │
  │                                  │  Required to answer "which VM    │
  │                                  │  cost the most?"                 │
  └──────────────────────────────────┴──────────────────────────────────┘
```

## 5. Cost Allocation -- Labels vs Tags

```
  ┌──────────────────────────────────┬──────────────────────────────────┐
  │              LABELS              │              TAGS                │
  ├──────────────────────────────────┼──────────────────────────────────┤
  │  key:value pairs                 │  IAM-controlled key:value        │
  │  Attached to resources/projects  │  Attached to resources           │
  │  Used for cost allocation        │  Used for IAM conditions and     │
  │                                  │  firewall rules                  │
  │                                  │                                  │
  │  PROPAGATE to billing exports    │  DO NOT propagate to billing     │
  │  ✓ Group costs by team:checkout  │  ✗ Cannot use for chargeback     │
  │  ✓ Group costs by env:prod       │                                  │
  └──────────────────────────────────┴──────────────────────────────────┘

  EXAM TRAP: "Tag resources by team for cost separation" ── WRONG, use LABELS.
```

## 7. Section 1.2 Cheat Sheet

```
  ┌──────────────────────────────────────────────────────────────────────────────┐
  │  1.2 QUICK REFERENCE                                                         │
  ├──────────────────────────────────────────────────────────────────────────────┤
  │  ARCHITECTURE   1 project ─► 1 billing account; 1 account ─► many projects   │
  │  HIERARCHY      Billing accounts live OUTSIDE org hierarchy                  │
  │  ACCOUNT TYPES  Self-serve (CC) vs Invoiced (enterprise)                     │
  │  LINKING ROLES  billing.user (acct) + billing.projectManager (project)       │
  │  BUDGETS        Alert ONLY, never hard-cap; thresholds are %                 │
  │  HARD CAP       Budget ─► Pub/Sub ─► Cloud Function disables billing         │
  │  EXPORTS        BigQuery (analyze) or Cloud Storage (archive); forward-only  │
  │  EXPORT SCHEMAS Standard / Detailed (per-resource) / Pricing data            │
  │  EXPORT SETUP   Console-only (gcloud cannot configure exports)               │
  │  CHARGEBACK     LABELS propagate to exports; TAGS do not                     │
  │  CALCULATOR     Forecast (NOT actual)                                        │
  │  REPORTS        Actual cost (NOT forecast)                                   │
  │  DISABLE BILL   Stops resources but keeps the project                        │
  └──────────────────────────────────────────────────────────────────────────────┘
```
