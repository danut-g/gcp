# 1.2 — Managing billing configuration

> **Exam guide reference:** Section 1.2. Sub-topics: creating billing accounts, linking projects to a billing account, billing budgets and alerts, billing exports.

---

## 1. Why this matters for the exam

Billing questions on the exam are not about *cost engineering* — they are about **structure and control**: who pays, how the costs are visible, and how to prevent surprises. You must know the difference between a billing account and a project, what permissions are required to link them, and how to set up the **alerts and exports** that let an organization actually monitor spend.

Expect questions like:

- A new project was created and no resources can be provisioned. Why? (Billing not linked, or the linker did not have permission.)
- A team needs to know when they reach 50% of their monthly budget. (Budget alert via Pub/Sub or email.)
- Finance wants every line item from every project in BigQuery for analysis. (Billing export to BigQuery.)

---

## 2. Core concepts

### 2.1 Billing accounts vs. projects

A **billing account** holds a payment method and accumulates charges. A **project** consumes resources. The two are linked: every project either has a billing account or it cannot use paid services.

- One billing account can pay for **many projects**.
- A project is linked to **exactly one** billing account at a time (it can be moved).
- Billing accounts live **outside** the project hierarchy — they are not inside an organization the way projects are, although they can be **owned** by an organization.

Two account types:

| Type | Who pays | Created via |
|---|---|---|
| **Self-serve** (online) | The credit card on file | `console.cloud.google.com` signup |
| **Invoiced** | Monthly invoice from Google | Negotiated with sales; common for enterprises |

### 2.2 Billing IAM roles

These are separate from project IAM and live on the billing account itself.

| Role | What it grants |
|---|---|
| **Billing Account Creator** (org-level) | Can create new billing accounts under the org |
| **Billing Account Administrator** | Manage everything on a billing account: payment, users, link/unlink projects |
| **Billing Account User** | Link projects to this billing account (but cannot manage it) |
| **Billing Account Viewer** | See charges and reports |
| **Project Billing Manager** (project-level) | Attach/detach a billing account from a single project |

The classic exam scenario: *"To link a new project to an existing billing account, what's the minimum role combination?"* Answer — **Billing Account User** on the billing account **and** **Project Billing Manager** on the project.

### 2.3 Budgets and alerts

A **budget** is a monitoring construct, not a hard cap. It does **not** stop spending — it raises an alert when thresholds are crossed.

- A budget targets a **billing account**, optionally scoped to specific projects, services, or labels.
- Thresholds are percentages of the budget amount: typical defaults are **50%, 90%, 100%**, but you set them.
- Alerts can go to **billing admins/users by email** or to a **Pub/Sub topic** for programmatic action (the way you implement "stop the spend" — a Cloud Function listens on the topic and disables billing on the project).

The amount can be a **specified amount** (flat dollar) or **last month's spend** (rolling target).

### 2.4 Billing exports

You enable an export per billing account; once on, it streams every line item to a destination.

| Destination | Use case |
|---|---|
| **BigQuery** | Detailed cost analytics, custom dashboards, joining cost data with internal data |
| **Cloud Storage** | Long-term archive, regulated retention |

Two BigQuery export schemas:
- **Standard usage cost** — per-SKU charges, the everyday format.
- **Detailed usage cost** — adds resource-level granularity (e.g. per-VM costs). Larger and more expensive to store, but answers "which VM cost the most".
- A separate **pricing data** export gives you the price list itself, useful for "what-if" cost modelling.

### 2.5 Cost reports and the billing console

Built-in tools you should know exist:

- **Reports** — interactive cost breakdown by project, service, SKU, region, label, time range.
- **Cost table** — flat tabular view of charges, exportable as CSV.
- **Cost breakdown** — separates list price, discounts, credits, taxes.
- **Pricing calculator** — estimates costs *before* you provision (`cloud.google.com/products/calculator`).

### 2.6 Labels and cost allocation

**Labels** are key/value pairs you attach to resources (and to projects). They are the standard mechanism for **chargeback** and **showback**: the billing export carries labels through, so you can group costs by `team:checkout`, `env:prod`, etc.

Labels are different from **tags** (which are used in IAM and firewalls). Don't confuse them on the exam.

## 3. Decision criteria

| Question | Rule of thumb |
|---|---|
| One billing account or many? | One per **legal entity / cost centre**. Multiple accounts are rarely necessary; multiple projects under one account is the norm. |
| How do I cap spending? | You don't, directly. A budget alert + Pub/Sub + Cloud Function that disables billing on the project is the supported pattern. |
| Should I export to BigQuery or Cloud Storage? | BigQuery for analysis, Cloud Storage for archival. You can do both. |
| Standard or detailed export? | Standard is enough for most teams; detailed only if you need per-resource attribution and accept the storage cost. |
| Per-team chargeback — labels or projects? | Projects are the cleanest boundary. Labels work when one project is shared across teams. |

## 4. Console walkthrough

- **Billing landing page** — *Navigation menu → Billing*. If you have multiple billing accounts you'll be asked which one to view.
- **Linking a project** — from the project: *Billing → Link a billing account*. From the billing account: *Account management → Projects → Add project*.
- **Budgets & alerts** — *Billing → Budgets & alerts → Create budget*. Pick scope (account / projects / services / labels), set amount, set thresholds, choose notification channels.
- **Billing export** — *Billing → Billing export*. Tabs for *BigQuery export* and *File export* (Cloud Storage). Choose dataset / bucket and the export turns on for all future usage.
- **Reports** — *Billing → Reports*. Default chart shows month-to-date by service; group/filter controls live on the right rail.
- **Pricing calculator** — separate site at `cloud.google.com/products/calculator`, not inside the console.

## 5. gcloud reference

Most billing operations are console-driven, but the CLI covers the essentials.

```bash
# List billing accounts you can see
gcloud billing accounts list

# Describe a billing account
gcloud billing accounts describe BILLING_ACCOUNT_ID

# Link / unlink a project
gcloud billing projects link    PROJECT_ID --billing-account=BILLING_ACCOUNT_ID
gcloud billing projects unlink  PROJECT_ID

# Show which billing account a project uses
gcloud billing projects describe PROJECT_ID

# Budgets (Cloud Billing Budgets API — the gcloud verbs live under `billing budgets`)
gcloud billing budgets list   --billing-account=BILLING_ACCOUNT_ID
gcloud billing budgets create --billing-account=BILLING_ACCOUNT_ID \
    --display-name="monthly-prod" --budget-amount=1000USD \
    --threshold-rule=percent=0.5 --threshold-rule=percent=0.9 --threshold-rule=percent=1.0
```

Billing exports are **only configurable in the console**, not via gcloud — a fact worth knowing for the exam.

## 6. Exam gotchas

- **A budget does not stop spending.** It only alerts. The "auto-shutoff" pattern requires Pub/Sub + Cloud Function.
- **You need two separate roles** to link a project to a billing account: Billing Account User on the billing side, Project Billing Manager on the project side.
- **A project can only link to one billing account at a time.** Switching is allowed; splitting between two is not.
- **Billing accounts are not inside the resource hierarchy.** Org IAM doesn't automatically grant billing roles — billing has its own IAM surface.
- **Disabling billing** on a project doesn't delete it; resources stop running but the project still exists. Re-enabling billing brings them back, with limits.
- **Labels propagate to billing exports**, **tags do not** (tags are an IAM/firewall concept on a different code path).
- **Exports are forward-only.** Turning on a BigQuery export today does not back-populate historical data.
- **Pricing calculator** vs. **cost reports** — the calculator is *forecasting*, reports are *actuals*. The exam likes to mix these up.

## 7. Practice scenarios

### Q1 — Linking a project to a billing account
A new engineer was given `roles/owner` on a project. They cannot link the project to the company's existing billing account. What additional role is required and where?

A. `roles/billing.user` on the project.
B. `roles/billing.user` on the billing account, plus `roles/billing.projectManager` on the project.
C. `roles/billing.admin` on the organization.
D. Owner is sufficient — there must be a billing account problem.

**Answer: B.** Linking a project to a billing account is an explicitly cross-resource action: the user needs **Billing Account User** on the billing account *and* **Project Billing Manager** on the project. Owner does not include billing-account-side permissions because billing accounts live outside the project hierarchy.

### Q2 — Capping spend
Management says "we cannot exceed $10,000 per month on this project under any circumstances." Which configuration delivers this?

A. Set a budget of $10,000 with a 100% threshold email alert.
B. Set a budget of $10,000 and configure a Pub/Sub notification that triggers a Cloud Function which disables billing on the project.
C. Set a quota on the project.
D. Use a billing alert with SMS notification.

**Answer: B.** Budgets in GCP **never cap spending automatically** — they only alert. The supported pattern for hard cutoff is a budget → Pub/Sub → Cloud Function that disables billing. A and D notify but don't stop spend. C confuses quotas (resource counts) with cost.

### Q3 — Detailed cost analysis
The finance team wants to attribute costs at the level of individual virtual machines, by team. What's the correct configuration?

A. Enable BigQuery export with the Standard usage cost schema and group by project.
B. Enable BigQuery export with the **Detailed usage cost** schema and use **labels** like `team:checkout`.
C. Use the Pricing Calculator to estimate per-VM costs.
D. Export billing to Cloud Storage and parse the CSVs in a spreadsheet.

**Answer: B.** Detailed usage cost gives per-resource granularity; labels propagate into the export and provide the team-level grouping. A's standard schema doesn't reach per-VM granularity. C forecasts, not actuals. D would work in theory but is far more cumbersome than BigQuery.

### Q4 — Multi-team billing
A startup wants one billing account but needs each team's costs separated for chargeback. What's the recommended structure?

A. One billing account, one project per team, billing export to BigQuery.
B. One billing account per team.
C. One project, multiple billing accounts (one per team).
D. Apply tags to resources by team.

**Answer: A.** Projects are the cleanest cost boundary; billing export already breaks costs out by project. B is unnecessary overhead — a single billing account aggregates correctly. C is impossible (project ↔ one billing account). D *tags* are an IAM/firewall concept and do not propagate to billing exports — **labels** do.

### Q5 — Budget alert recipients
A budget reaches 90%; you want the alert to go to the cost-engineering team via Slack. What is required?

A. Configure email recipients on the budget.
B. Configure a Pub/Sub topic on the budget; subscribe a Cloud Function that posts to Slack.
C. Use the Slack-native budget integration in the GCP console.
D. Export billing to BigQuery and run a scheduled query that posts to Slack.

**Answer: B.** Budgets support email and Pub/Sub. There is no first-party Slack integration; the standard pattern is Pub/Sub → Cloud Function → Slack webhook. A only emails billing admins/users (no Slack). D is a far more roundabout path.

## 8. Hands-on labs

### Lab 1 — Verify and manage project billing
**Goal:** See which billing account a project uses, and link/unlink projects.

**Console:**
1. Confirm the project context (top bar).
2. *Navigation menu → Billing*.
3. If the project has no billing account, you'll see *"This project has no billing account"* with a **Link a billing account** button — click it, pick the account, **Set account**.
4. To unlink: *Billing → Account management → Manage billing account → Disable billing*. The project still exists; resources stop running.
5. To switch billing account on a linked project: *Billing → Account management → Change billing account*.

To see all projects under one billing account:
1. Switch the billing context (top bar) to the billing account.
2. *Account management → Projects*. The list shows project name, ID, and link state.

**gcloud:**
```bash
# Confirm what billing account a project uses
gcloud billing projects describe PROJECT_ID

# Link / unlink
gcloud billing projects link   PROJECT_ID --billing-account=BILLING_ACCOUNT_ID
gcloud billing projects unlink PROJECT_ID

# List billing accounts visible to you
gcloud billing accounts list
```

### Lab 2 — Create a budget with thresholds and Pub/Sub alerting
**Goal:** Get alerts at 50/90/100% with Pub/Sub for programmatic action.

**Console:**
1. *Navigation menu → Billing → (billing account) → Budgets & alerts → Create budget*.
2. **Scope:** select project(s) / service(s) / label(s) the budget should cover. Leave default to cover the whole account.
3. **Amount:** choose *Specified amount* and enter `$1,000` (or *Last month's spend* for a rolling target).
4. **Actions** (thresholds): the form pre-fills 50%, 90%, 100% — adjust if needed (e.g. add 25%).
5. **Manage notifications:**
   - Tick **Email alerts to billing admins and users**.
   - To add Pub/Sub: tick **Connect a Pub/Sub topic** → pick or create a topic in the project (e.g. `billing-alerts`).
6. Click **Finish**.

To turn that Pub/Sub topic into an automatic billing-disable, deploy a Cloud Function with a Pub/Sub trigger that calls the Cloud Billing API to unlink the project.

**gcloud:**
```bash
gcloud billing budgets create \
    --billing-account=BILLING_ACCOUNT_ID \
    --display-name="prod-monthly" \
    --budget-amount=1000USD \
    --threshold-rule=percent=0.5 \
    --threshold-rule=percent=0.9 \
    --threshold-rule=percent=1.0 \
    --notifications-rule-pubsub-topic=projects/PROJECT_ID/topics/billing-alerts

# List / describe / delete
gcloud billing budgets list   --billing-account=BILLING_ACCOUNT_ID
gcloud billing budgets describe BUDGET_ID --billing-account=BILLING_ACCOUNT_ID
gcloud billing budgets delete   BUDGET_ID --billing-account=BILLING_ACCOUNT_ID
```

### Lab 3 — Enable billing export to BigQuery
**Goal:** Stream every line item to a BigQuery dataset for analysis.

**Console (only — exports are not configurable via gcloud):**
1. Create the destination dataset first: *BigQuery → (project) → Create dataset*. Pick a multi-region (`EU` or `US`) and a friendly ID (e.g. `billing_export`).
2. Switch context to the **billing account** (top bar).
3. *Billing → Billing export*.
4. Tabs: **BigQuery export** (Standard usage cost / Detailed usage cost / Pricing data).
5. Click **Edit settings** on *Standard usage cost*.
6. Choose the project and dataset created in step 1.
7. **Save**. Future usage flows in (no historical backfill).

Tip: enable both *Standard* and *Detailed* if you need per-resource cost — they go into separate tables (`gcp_billing_export_v1_*` and `gcp_billing_export_resource_v1_*`).

### Lab cleanup
- Budgets are free to keep around — leave them unless you're decluttering.
- The BigQuery export dataset itself stores data and incurs storage costs; delete the dataset if you stop the export and want to clean up: *BigQuery → (dataset) → Delete*.
