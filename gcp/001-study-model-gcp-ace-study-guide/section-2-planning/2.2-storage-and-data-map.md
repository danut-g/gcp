## 3. Cloud Storage -- Locations and Classes

```
                            ┌── Region
                            │     One region (multi-zone)
                            │     Lowest latency near compute
                            │
        Bucket Location ────┤── Dual-region
                            │     Two specific regions, sync replicated
                            │
                            └── Multi-region
                                  Continent (us / eu / asia)
                                  Max availability for global content
```

### Storage Classes

```
  ┌─────────────┬──────────────┬─────────────────┬────────────────────────┐
  │  Class      │  Min duration│  Retrieval cost │  Access pattern        │
  ├─────────────┼──────────────┼─────────────────┼────────────────────────┤
  │  Standard   │  none        │  none           │  Hot, frequent access  │
  │  Nearline   │  30 days     │  per-GB fee     │  ~once per month       │
  │  Coldline   │  90 days     │  higher fee     │  ~few times per year   │
  │  Archive    │  365 days    │  highest fee    │  almost never          │
  └─────────────┴──────────────┴─────────────────┴────────────────────────┘

  WARNING: Min storage duration is per-OBJECT.
  Switching to Coldline & deleting next day still costs 90 days.
```

## 4. Cloud SQL -- HA vs Read Replicas

```
                       Cloud SQL Primary (zone A)
                              │ │
                              │ └────── synchronous ─────────►  HA STANDBY
                              │                                  (zone B,
                              │                                   NOT queryable)
                              │
                              └────── asynchronous ────────►  READ REPLICA
                                                              (queryable, can
                                                               be cross-region)

  ┌─────────────────────────────┬────────────────────────────────────────┐
  │  HA STANDBY                 │  READ REPLICA                          │
  ├─────────────────────────────┼────────────────────────────────────────┤
  │  Synchronous, RPO = 0       │  Asynchronous, lag possible            │
  │  Auto-failover (~1-2 min)   │  Manual promotion (DR pattern)         │
  │  Same connection name       │  Distinct endpoint                     │
  │  NOT queryable              │  Queryable (offload reads)             │
  │  --availability=REGIONAL    │  Cross-region OK for DR                │
  └─────────────────────────────┴────────────────────────────────────────┘
```

## 5. Filestore vs NetApp Volumes

```
  ┌──────────────────────────────────┬──────────────────────────────────┐
  │  FILESTORE                       │  NETAPP VOLUMES                  │
  ├──────────────────────────────────┼──────────────────────────────────┤
  │  NFS only (NFSv3 / v4.1)         │  NFS + SMB + dual-protocol       │
  │  Tiers:                          │  ONTAP features:                 │
  │    Basic HDD / Basic SSD         │    Snapshots                     │
  │    Zonal (high-scale)            │    FlexClone                     │
  │    Regional (sync replicated)    │    Dedup                         │
  │    Enterprise (SAP, EDA)         │    SnapMirror to/from on-prem    │
  │                                  │                                  │
  │  Use: Linux POSIX shares         │  Use: SMB / Windows / on-prem    │
  │                                  │       NetApp migration           │
  └──────────────────────────────────┴──────────────────────────────────┘

  EXAM TRAP: Windows lift-and-shift needing SMB ──► NetApp Volumes
                                                    (NOT Filestore)
```

### Storage Transfer vs Transfer Appliance

```
  ┌──────────────────────────────────┬──────────────────────────────────┐
  │  STORAGE TRANSFER SERVICE        │  TRANSFER APPLIANCE              │
  ├──────────────────────────────────┼──────────────────────────────────┤
  │  Online, over the network        │  OFFLINE, ship a physical box    │
  │  Schedule, filter, bw cap        │  7 / 40 / 300 TB devices         │
  │  Pub/Sub on completion           │  Used when WAN is too slow       │
  └──────────────────────────────────┴──────────────────────────────────┘

  RULE: 200 TB on 50 Mbps would take ~370 days ──► Appliance, not STS.
```

## 7. Multi-Region Redundancy by Product

```
  ┌──────────────────────┬────────────────────────────────────────────┐
  │  Product             │  Multi-region strategy                     │
  ├──────────────────────┼────────────────────────────────────────────┤
  │  Cloud Storage       │  Multi-region or dual-region bucket        │
  │  Cloud SQL           │  Regional HA + cross-region read replica   │
  │                      │  (manual promotion for DR)                 │
  │  Spanner             │  Multi-region instance config (built-in)   │
  │  Firestore           │  Pick multi-region at create (PERMANENT)   │
  │  BigQuery            │  Dataset location at create (PERMANENT)    │
  │  Bigtable            │  Replication with extra cluster(s)         │
  │  Pub/Sub             │  Already global; per-region storage option │
  └──────────────────────┴────────────────────────────────────────────┘

  REPLICATION ≠ BACKUP
  ────────────────────
  Replication = availability     Backup = "oops, I deleted the table"
  You usually need BOTH.
```

## 8. Section 2.2 Cheat Sheet

```
  ┌──────────────────────────────────────────────────────────────────────────────┐
  │  2.2 QUICK REFERENCE                                                         │
  ├──────────────────────────────────────────────────────────────────────────────┤
  │  BUCKET NAMES   Globally unique forever                                      │
  │  CLASSES        Standard / Nearline 30d / Coldline 90d / Archive 365d        │
  │  MIN DURATION   Per-object; switch+delete still pays the minimum             │
  │  LIFECYCLE      Async (~daily evaluation), not millisecond                   │
  │  RETENTION      Lockable, irrevocable                                        │
  │  ACCESS         Uniform Bucket-Level Access is default                       │
  │  CLOUD SQL HA   Sync standby (NOT queryable); != read replicas               │
  │  SPANNER        Global ACID; expensive; read scenarios carefully             │
  │  ALLOYDB        PG when Cloud SQL too small                                  │
  │  FIRESTORE      Native vs Datastore mode is PERMANENT                        │
  │  BIGTABLE       Wide-column, IoT/time-series; no free tier                   │
  │  BIGQUERY       Dataset location PERMANENT; on-demand vs slot pricing        │
  │  FILESTORE      NFS only (no SMB)                                            │
  │  NETAPP         NFS + SMB + dual; ONTAP features                             │
  │  LOAD: STS      Online cloud-to-cloud / on-prem with agents                  │
  │  LOAD: APPLIANCE  Physical box for >TBs over slow links                      │
  │  LOAD: DMS      Online DB migration                                          │
  │  REDUNDANCY     Replication != backup; need both                             │
  └──────────────────────────────────────────────────────────────────────────────┘
```
