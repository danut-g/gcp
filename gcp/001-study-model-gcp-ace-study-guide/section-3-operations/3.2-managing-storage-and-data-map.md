# 3.2 -- Visual Map: Managing Storage and Data

---

## 1. Cloud Storage Operations

```
                            ┌── Uniform Bucket-Level Access (DEFAULT)
                            │     IAM only, simpler
                            │
        Access Control ─────┤── Fine-grained ACLs (legacy)
                            │     per-object permissions
                            │
                            ├── Public access prevention (org policy)
                            │
                            └── Signed URLs
                                  Time-bounded download/upload links
                                  No IAM required for the recipient


                            ┌── Versioning
                            │     keep prior copies on overwrite/delete
                            │
        Protection ─────────┤── Retention policy (lockable)
                            │     can't delete before N seconds
                            │
                            └── Object holds
                                  - event-based
                                  - temporary
```

### Object Lifecycle Management

```
  Day 0         Day 30          Day 90           Day 365
  ┌────────┐   ┌──────────┐    ┌──────────┐    ┌────────┐
  │STANDARD│ ─►│ NEARLINE │ ─► │ COLDLINE │ ─► │ARCHIVE │
  └────────┘   └──────────┘    └──────────┘    └────────┘

   Lifecycle rule conditions you'll see:
     - age (days)
     - matchesStorageClass [STANDARD, NEARLINE, ...]
     - isLive   (current vs non-current versions)
     - createdBefore
     - numNewerVersions

   Actions:
     - SetStorageClass (transition)
     - Delete

   EVALUATION: Daily, async — NOT instant.
```

### Encryption Operational

```
                            ┌── GMEK (default)
                            │     Google-managed, you do nothing
                            │
        Encryption ─────────┤── CMEK
                            │     YOU manage in Cloud KMS
                            │     Rotate, revoke, audit
                            │
                            └── CSEK
                                  YOU supply the raw key on every request
                                  Google never stores it
```

## 3. Backups and Restores

```
                            ┌── Cloud SQL
                            │     - Automated daily backups (default)
                            │     - On-demand backups (manual)
                            │     - PITR via binary logs (must enable)
                            │     - Clone to a new instance at PIT
                            │
                            ├── BigQuery
                            │     - Time travel (default 7 days)
                            │     - Table snapshots (longer-term)
                            │     - Dataset copy across regions
        Backup Options ─────┤
                            ├── Firestore
                            │     - Export to GCS bucket
                            │     - Schedule via Cloud Scheduler
                            │
                            ├── Spanner
                            │     - Backups (in same instance/region)
                            │     - Restore to new instance
                            │
                            └── Bigtable
                                  - Backups per cluster
                                  - Restore to a new table
```

### Point-in-Time Recovery (Cloud SQL)

```
  TIMELINE:
  ──────────────────────────────────────────────────────────────────►
   T0           T1            T2            T3         T4 (now)
  daily         binary        binary        broken     "oh no"
  backup        log           log           change

   PITR pattern:
   1. Find PIT just BEFORE the broken change (T2)
   2. gcloud sql instances clone SOURCE NEW --point-in-time=T2
   3. Application points at NEW
   4. Sanity-check, optionally swap names
```

## 4. Reviewing Job Status

```
                            ┌── BigQuery Jobs
                            │     - Query / Load / Extract / Copy
                            │     - bq ls -j PROJECT
                            │     - Job history shows bytes BILLED
                            │
        Job Inspection ─────┤── Dataflow Jobs
                            │     - Drain  (graceful, finish in-flight)
                            │     - Cancel (abort, may lose work)
                            │     - Update (in-place, compatible upgrade)
                            │
                            └── Database Center
                                  Cross-DB observability for SQL/NoSQL
```

### Drain vs Cancel

```
  ┌──────────────────────────────────┬──────────────────────────────────┐
  │  DRAIN                           │  CANCEL                          │
  ├──────────────────────────────────┼──────────────────────────────────┤
  │  Stop accepting new data         │  Stop NOW                        │
  │  Process in-flight to completion │  In-flight work may be lost      │
  │  Used before upgrade / shutdown  │  Used when job is stuck/wrong    │
  └──────────────────────────────────┴──────────────────────────────────┘
```

## 6. Operations Quick Picks

```
  ┌──────────────────────────────────────┬──────────────────────────────┐
  │  Task                                │  Action                      │
  ├──────────────────────────────────────┼──────────────────────────────┤
  │  Share one file with someone briefly │  Signed URL (time-bounded)   │
  │  Delete after N days                 │  Lifecycle Delete rule       │
  │  Ransomware-resistant retention      │  Bucket retention + LOCK     │
  │  Recover Cloud SQL after bad UPDATE  │  PITR clone to before T      │
  │  Recover BQ table dropped 2h ago     │  Time travel `FOR SYSTEM_TIME│
  │  Pause Dataflow for upgrade          │  Drain (NOT cancel)          │
  │  Audit who accessed a BQ table       │  Enable Data Access logs     │
  │  Cheap GCS soft-delete               │  Versioning + lifecycle      │
  └──────────────────────────────────────┴──────────────────────────────┘
```

## 7. Section 3.2 Cheat Sheet

```
  ┌──────────────────────────────────────────────────────────────────────────────┐
  │  3.2 QUICK REFERENCE                                                         │
  ├──────────────────────────────────────────────────────────────────────────────┤
  │  ACCESS         Uniform Bucket-Level Access default; signed URLs for shares  │

  │  ENCRYPTION     GMEK / CMEK / CSEK                                           │
  │  CLOUD SQL PITR Enable binary logs; clone to a PIT                           │
  │  BQ TIME TRAVEL Default 7 days; FOR SYSTEM_TIME AS OF                        │
  │  BQ SNAPSHOTS   Long-term, cheap, point-in-time                              │
  │  FIRESTORE BKP  Export to GCS, scheduled via Cloud Scheduler                 │
  │  DATAFLOW       Drain (graceful) vs Cancel (abort) vs Update (in-place)      │
  │  COST CALC      Pricing Calculator forecasts; Reports = actual               │
  │  AUDIT BQ READS Enable Data Access logs (off by default)                     │
```
