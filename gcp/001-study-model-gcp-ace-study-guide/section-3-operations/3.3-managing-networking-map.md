# 3.3 -- Visual Map: Managing Networking Resources

## 1. Subnet Operations

```
                            ┌── Add a subnet
                            │     - Pick region
                            │     - Pick CIDR /16 .. /29
                            │     - gcloud compute networks subnets create
                            │
        Subnet Lifecycle ───┤── Expand IP range
                            │     - Only GROW, never shrink
                            │     - gcloud compute networks subnets
                            │       expand-ip-range
                            │
                            └── Secondary ranges (Alias IPs)
                                  - Used by GKE pods/services
                                  - Multiple per subnet OK
                                  - Routed within VPC
```

### Add vs Expand

```
                              Need a NEW network slice?
                                       │
                              ┌────────┴────────┐
                              ▼                 ▼
                            YES                 NO  (existing slice too small)
                              │                 │
                              ▼                 ▼
                  ┌────────────────────┐  ┌─────────────────────┐
                  │  ADD a new subnet  │  │  EXPAND IP range    │
                  │  (pick CIDR, region│  │  - cannot shrink    │
                  └────────────────────┘  │  - cannot overlap   │
                                          └─────────────────────┘
```

## 2. Static IP Addresses

```
  ┌──────────────────────────────────┬──────────────────────────────────┐
  │  INTERNAL (RFC1918)              │  EXTERNAL (public)               │
  ├──────────────────────────────────┼──────────────────────────────────┤
  │  Inside the VPC                  │  Internet-facing                 │
  │  Regional only                   │  Regional or Global              │
  │  Free                            │  Costs while reserved + unused   │
  └──────────────────────────────────┴──────────────────────────────────┘

  ┌──────────────────────────────────┬──────────────────────────────────┐
  │  EPHEMERAL                       │  STATIC (RESERVED)               │
  ├──────────────────────────────────┼──────────────────────────────────┤
  │  Auto-assigned, may change       │  Reserved, won't change          │
  │  Released when VM deletes        │  Persists past VM deletion       │
  │  Free                            │  Charge if reserved & unused     │
  └──────────────────────────────────┴──────────────────────────────────┘

  EXAM PATTERN: LB needs an IP that won't change ──► Reserve a static.
```

### Premium vs Standard Tier (for external IPs)

```
                            ┌── Premium  → Google backbone, global LB capable
        Network Tier ───────┤
                            └── Standard → public internet, regional only
```

## 3. Routes

```
                              ┌── System-generated routes
                              │     - Subnet routes (one per subnet)
                              │     - Default route 0.0.0.0/0 → internet GW
                              │
        VPC Routes ───────────┤── Custom static routes
                              │     - Next hop options:
                              │         default-internet-gateway
                              │         instance (NVA)
                              │         internal LB
                              │         VPN tunnel
                              │         peering
                              │     - Priority: lower wins
                              │
                              └── Tag-based routes
                                    - Apply only to VMs with tag
```

### When to Add a Custom Route

```
  ┌──────────────────────────────────────────────────────────────────────┐
  │  Force traffic through a network virtual appliance (NVA / firewall)  │
  │  Override the default route to send egress through Cloud VPN         │
  │  Reach a specific peer-VPC subnet that the system route can't        │
  └──────────────────────────────────────────────────────────────────────┘
```

## 4. Cloud DNS

```
                            ┌── Public managed zone
                            │     internet-resolvable, e.g. example.com
                            │
                            ├── Private zone
                            │     resolvable only inside given VPC(s)
        Cloud DNS Zones ────┤
                            ├── Forwarding zone
                            │     resolve via on-prem (AD DNS, etc.)
                            │
                            └── Peering zone
                                  share zone across peered VPCs


  Record types you'll see: A, AAAA, CNAME, MX, TXT, SRV
  DNSSEC available on public zones.
```

## 5. Cloud NAT

```
                                       Cloud NAT
                                       ▲
                                       │ (outbound only, no inbound)
            ┌──────────────────────────┘
            │
    ┌───────────────────────────────────────┐
    │              VPC                      │
    │   ┌──────────┐    ┌──────────┐        │
    │   │ Private  │    │ Private  │        │
    │   │  VM      │    │   VM     │        │
    │   │ no ext IP│    │ no ext IP│        │
    │   └──────────┘    └──────────┘        │
    └───────────────────────────────────────┘
                                       │
                                       ▼
                                    Internet


  ┌──────────────────────────────────────────────────────────────────────┐
  │  Cloud NAT key facts                                                 │
  ├──────────────────────────────────────────────────────────────────────┤
  │  - Outbound only (private VMs reach internet, no inbound from net)   │
  │  - Per region; needs Cloud Router                                    │
  │  - Manual or automatic IP allocation                                 │
  │  - Logs and metrics available                                        │
  └──────────────────────────────────────────────────────────────────────┘
```

## 6. Private Google Access

```
                                  Google APIs
                                  (BigQuery, GCS, etc.)
                                       ▲
                                       │  via Google's private VIPs
            ┌──────────────────────────┘
            │  no external IP, no Cloud NAT needed for *.googleapis.com
    ┌───────────────────────────────────────┐
    │              VPC                      │
    │   ┌──────────┐                        │
    │   │ Private  │                        │
    │   │  VM      │                        │
    │   │ PGA: ON  │  ◄── enable on subnet  │
    │   └──────────┘                        │
    └───────────────────────────────────────┘


  PGA vs Cloud NAT
  ────────────────
  PGA       reaches Google APIs without external IP
  Cloud NAT reaches the public internet (third-party HTTPS, apt repos)
  You may need BOTH on the same subnet.
```

## 7. Quick Picks

```
  ┌──────────────────────────────────────┬──────────────────────────────┐
  │  Task                                │  Pick                        │
  ├──────────────────────────────────────┼──────────────────────────────┤
  │  GKE pod IP space                    │  Subnet secondary range      │
  │  Avoid LB IP changes                 │  Reserve static external IP  │
  │  Internal name "db.corp"             │  Cloud DNS PRIVATE zone      │
  │  Resolve on-prem hostnames           │  DNS forwarding zone         │
  │  Outbound for private VMs            │  Cloud NAT                   │
  │  Reach Google APIs without ext IP    │  Private Google Access       │
  │  Force traffic via NVA               │  Custom route, instance hop  │
  │  Subnet too small                    │  expand-ip-range (only grow) │
  └──────────────────────────────────────┴──────────────────────────────┘
```

## 8. Section 3.3 Cheat Sheet

```
  ┌──────────────────────────────────────────────────────────────────────────────┐
  │  3.3 QUICK REFERENCE                                                         │
  ├──────────────────────────────────────────────────────────────────────────────┤
  │  SUBNETS        Add new or EXPAND existing (only grow, never shrink)         │
  │  SECONDARY RNG  Alias IPs; main use = GKE pods/services                      │
  │  STATIC IPs     Internal vs External; Regional vs Global                     │
  │  RESERVE        Use static IPs for LBs, NAT, anything endpoint-stable        │
  │  ROUTES         System + Custom (priority, lower wins)                       │
  │  NEXT HOPS      Internet GW / instance / ILB / VPN tunnel / peering          │
  │  CLOUD DNS      Public + Private + Forwarding + Peering zones                │
  │  CLOUD NAT      Outbound only; per region; needs Cloud Router                │
  │  PGA            Reach Google APIs from VMs without external IPs              │
  │  PGA vs NAT     Both may be needed (Google APIs vs third-party internet)    │
  └──────────────────────────────────────────────────────────────────────────────┘
```
