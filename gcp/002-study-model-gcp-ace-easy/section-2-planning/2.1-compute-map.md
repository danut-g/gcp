## 7. GKE -- Cluster Topologies

```
  ┌──────────────────────────────────┬──────────────────────────────────┐
  │  ZONAL                           │  REGIONAL  (RECOMMENDED PROD)    │
  │  - Control plane in 1 zone       │  - Control plane in 3 zones      │
  │  - Default node pool in 1 zone   │  - Nodes spread across zones     │
  │  - Cheapest, weakest HA          │  - Survives zone failure         │
  └──────────────────────────────────┴──────────────────────────────────┘

  ┌──────────────────────────────────────────────────────────────────────┐
  │  PRIVATE CLUSTER                                                     │
  │  - Nodes have ONLY internal IPs                                      │
  │  - Control plane on a private endpoint                               │
  │  - Still needs egress (Cloud NAT or PGA) to pull images              │
  │  - Master authorized networks limit who reaches the endpoint         │
  └──────────────────────────────────────────────────────────────────────┘
```

### Standard vs Autopilot

```
  ┌──────────────────────────────────┬──────────────────────────────────┐
  │  GKE STANDARD                    │  GKE AUTOPILOT                   │
  ├──────────────────────────────────┼──────────────────────────────────┤
  │  Pay for: nodes + cluster fee    │  Pay for: pods (CPU/mem requests)│
  │  Configure: node pools           │  Configure: workloads ONLY       │
  │  Choose: machine types, taints   │  Google chooses nodes for you    │
  │  Scale: HPA + VPA + Cluster AS   │  Same autoscalers, hands-off     │
  └──────────────────────────────────┴──────────────────────────────────┘

  EXAM TIP: "paying for unused node capacity" ──► Autopilot or Cloud Run
```

### GKE Autoscalers

```
                       ┌── HPA (Horizontal Pod Autoscaler)
                       │     scales POD COUNT inside a Deployment
                       │
   GKE Autoscalers ────┤── VPA (Vertical Pod Autoscaler)
                       │     adjusts pod CPU/memory REQUESTS
                       │     don't combine VPA + HPA on memory
                       │
                       └── Cluster Autoscaler
                             scales NODES (machines) in a node pool
```

## 8. Cloud Run -- Revisions & Traffic

```
  ┌──────────────────────────────────────────────────────────────────────┐
  │  Each "deploy" creates a NEW REVISION                                │
  └──────────────────────────────────────────────────────────────────────┘

         Revision 00001          Revision 00002          Revision 00003
         (older)                  (older)                 (newest)
         ┌──────────┐             ┌──────────┐           ┌──────────┐
         │  v1.0    │             │  v1.1    │           │  v1.2    │
         └────┬─────┘             └────┬─────┘           └────┬─────┘
              │                        │                      │
              │                        │                      │
              └────────────┬───────────┴──────────┬───────────┘
                           │ traffic split        │
                           ▼                      ▼
                    ┌──────────┐            ┌──────────┐
                    │   90%    │            │   10%    │   <-- canary
                    └──────────┘            └──────────┘

  ROLLBACK = update-traffic to send 100% to a previous revision.
```

### Cloud Run Knobs

```
  ┌──────────────────────────────────┬──────────────────────────────────┐
  │  Concurrency (default 80)        │  How many requests per instance  │
  │  CPU allocation                  │  "during requests" or "always"   │
  │  Min instances                   │  Keep N warm (avoid cold starts) │
  │  Max instances                   │  Cap blast radius                │
  │  Startup CPU boost               │  Faster cold-start warm-up       │
  │  Service vs Job                  │  Long-running HTTP vs run-once   │
  └──────────────────────────────────┴──────────────────────────────────┘
```

```
  ┌──────────────────────────────────────────────────────────────────────────────┐
  │  2.1 QUICK REFERENCE                                                         │
  ├──────────────────────────────────────────────────────────────────────────────┤
  │  CONTINUUM      CE ─► GKE Std ─► GKE Auto ─► Cloud Run ─► Functions          │

  │  SPOT VMs       Up to 91% off, pre-empted any time, requires TERMINATE       │
  │  REGIONAL PD    Sync 2-zone replica = HA self-managed DB answer              │
  │  LOCAL SSD      Ephemeral; lost on VM stop                                   │
  │  TEMPLATES      Immutable; new template + rolling update to change           │
  │  AUTOSCALE MIG  CPU / LB cap / Cloud Monitoring metric / Pub/Sub / Schedule  │
  │  AUTO-HEAL MIG  Health check failures replace VMs                            │
  │  GKE TOPOLOGY   Regional > Zonal for prod; Private = no public IPs           │
  │  GKE AUTOSCALE  HPA pods / VPA requests / Cluster AS nodes                   │
  │  CLOUD RUN COLD min-instances=N to keep warm                                 │
  │  TRAFFIC SPLIT  Canary by % across revisions; rollback = traffic flip        │
  │  EVENTARC       Modern unified router, CloudEvents format                    │
  │  KUBECTL        Needs gke-gcloud-auth-plugin after recent gcloud             │
  └──────────────────────────────────────────────────────────────────────────────┘
```
