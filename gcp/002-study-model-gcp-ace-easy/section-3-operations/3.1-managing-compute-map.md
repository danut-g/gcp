# 3.1 -- Visual Map: Managing Compute Resources

---

## 1. Connecting to Compute Engine

```
                                 ┌── Browser SSH (one-click, console)
                                 │
                                 ├── gcloud compute ssh NAME --zone=Z
                                 │
        Linux VM ────────────────┤── IAP tunneling  (PRIVATE VMs)
                                 │     gcloud compute ssh ... --tunnel-through-iap
                                 │     needs roles/iap.tunnelResourceAccessor
                                 │
                                 └── Local SSH client + OS Login

                                 ┌── RDP from console
                                 │     "Set Windows password" → download .rdp
        Windows VM ──────────────┤
                                 ├── Microsoft Remote Desktop client
                                 │
                                 └── IAP TCP tunnel for port 3389
                                       gcloud compute start-iap-tunnel
```

### OS Login vs Metadata Keys

```
  ┌──────────────────────────────────┬──────────────────────────────────┐
  │  OS LOGIN  (RECOMMENDED)         │  METADATA SSH KEYS  (legacy)     │
  ├──────────────────────────────────┼──────────────────────────────────┤
  │  IAM-controlled                  │  Stored in project/instance meta │
  │  roles/compute.osLogin (login)   │  Per-VM or per-project keys      │
  │  roles/compute.osAdminLogin      │  Two managed lists, easy to drift│
  │  Audit-logged                    │                                  │
  │  Supports 2FA                    │                                  │
  └──────────────────────────────────┴──────────────────────────────────┘

  EXAM TIP: OS Login + metadata keys coexist awkwardly. Best practice is
            enable OS Login project-wide and remove metadata keys.
```

## 2. Snapshots, Images, Machine Images

```
                            ┌── SNAPSHOT
                            │     - Incremental backup of a disk
                            │     - Stored as GCS objects
                            │     - Can copy across regions
                            │     - Snapshot SCHEDULE = resource policy
                            │       attached to a disk
                            │
        Disk → bytes ───────┤── CUSTOM IMAGE
                            │     - Bake from a configured disk
                            │     - Image families for rolling updates
                            │     - Use as the boot template
                            │
                            └── MACHINE IMAGE
                                  - Whole-VM template
                                  - All disks + metadata + IAM + tags
                                  - Best for "clone this whole VM"
```

### When to Pick Which

```
  ┌──────────────────────────────────────┬──────────────────────────────┐
  │  Need                                │  Pick                        │
  ├──────────────────────────────────────┼──────────────────────────────┤
  │  Daily backup of a data disk         │  Snapshot schedule           │
  │  Build a "golden" boot disk          │  Custom image                │
  │  Recreate the entire VM elsewhere    │  Machine image               │
  │  Backup before risky upgrade         │  Manual snapshot             │
  └──────────────────────────────────────┴──────────────────────────────┘
```

## 3. GKE -- Operating It

```
                                       ┌── kubectl get nodes / pods
                                       │
                            Inventory ─┤── Console: Workloads tab
                                       │
                                       └── Stackdriver / Cloud Monitoring


                                       ┌── Workload Identity (RECOMMENDED)
                                       │     KSA bound to GSA
                                       │     no keys mounted
                                       │
       Auth GCP from Pod ──────────────┤── Service Account JSON keys
                                       │     (avoid; org policy can disable)
                                       │
                                       └── Default node SA (last resort)


                                       ┌── Add a pool
                                       ├── Different machine types per pool
                            Node Pools ┤── Taints + tolerations to target
                                       └── Per-pool cluster autoscaler
```

### Workload Identity Flow

```
  ┌─────────────────┐                         ┌──────────────────────┐
  │  Kubernetes SA  │   bound via IAM         │  Google Service Acct │
  │   wi-ksa        │  ◄────────────────────► │   sa@proj.iam        │
  │                 │   roles/iam.            │                      │
  │  in namespace   │   workloadIdentityUser  │  has actual GCP      │
  │  default        │                         │  permissions         │
  └────────┬────────┘                         └──────────────────────┘
           │
           ▼
  ┌──────────────────────────┐
  │  Pod uses               │
  │  serviceAccountName:    │
  │   wi-ksa                │
  │  ──► acts as the GSA    │
  └──────────────────────────┘
```

### HPA / VPA / Cluster Autoscaler

```
                                ┌── HPA (Horizontal Pod Autoscaler)
                                │     scales POD COUNT (replicas)
                                │     signals: CPU, mem, custom metric
                                │
        Three Autoscalers ──────┤── VPA (Vertical Pod Autoscaler)
                                │     adjusts POD CPU/MEM REQUESTS
                                │     don't combine with HPA on memory
                                │
                                └── Cluster Autoscaler
                                      adds/removes NODES in a node pool
                                      respects min/max per pool

  RULE: pods Pending? ──► is it pod request vs node capacity (CA?) or
                          pool max-nodes already hit (raise cap?) or
                          pool taints excluding the pod (toleration?)
```

### K8s Resources to Recognise

```
  Deployment      Stateless replicas              (web, API)
  StatefulSet     Stateful w/ stable hostnames    (databases, queues)
  DaemonSet       One per node                    (log/metric agents)
  Job             Run-to-completion               (one-shot batch)
  CronJob         Scheduled Job                   (periodic batch)
  Service         Network endpoint                (ClusterIP/NodePort/LB)
  Ingress         L7 routing                      (host/path → service)
```

## 4. Cloud Run -- Operating It

```
  ┌──────────────────────────────────────────────────────────────────────┐
  │  Each gcloud run deploy creates a NEW REVISION                       │
  └──────────────────────────────────────────────────────────────────────┘

         Revision-001 ──┐
         (90% traffic)  │
                        ├──►  Cloud Run service URL
         Revision-002 ──┘
         (10% traffic, canary)


  ROLLBACK   = update-traffic to send 100% to a previous revision
  CANARY     = update-traffic split N% to new revision
  DEPLOY     = gcloud run deploy --no-traffic, then promote
```

### Autoscaling Knobs

```
  ┌──────────────────────────────────┬──────────────────────────────────┐
  │  Min instances                   │  Keep N warm (avoid cold starts) │
  │  Max instances                   │  Cap blast radius                │
  │  Concurrency (default 80)        │  Requests per instance           │
  │  CPU allocation                  │  during requests / always        │
  │  Startup CPU boost               │  Faster warm-up                  │
  └──────────────────────────────────┴──────────────────────────────────┘

  COLD START LATENCY  ──►  bump min-instances=1
  RUNAWAY COST         ──►  cap max-instances
  BG WORK REQUIRED     ──►  CPU allocation = always
```

## 5. Decision Quick Picks

```
  ┌──────────────────────────────────────┬──────────────────────────────┐
  │  Task                                │  Action                      │
  ├──────────────────────────────────────┼──────────────────────────────┤
  │  SSH a private VM                    │  --tunnel-through-iap         │
  │  Daily disk backup                   │  Snapshot schedule policy    │
  │  Build a "golden VM"                 │  Custom image (image family) │
  │  Clone whole VM into a new project   │  Machine image               │
  │  Pod calls BigQuery securely         │  Workload Identity           │
  │  Stuck pending pods                  │  Inspect requests vs nodes   │
  │  Roll back Cloud Run                 │  update-traffic to old rev   │
  │  Reduce Cloud Run cold starts        │  --min-instances=1           │
  └──────────────────────────────────────┴──────────────────────────────┘
```
